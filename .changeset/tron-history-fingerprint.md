Tron history no longer loses transactions that share a block timestamp. Pages were time windows (`max_timestamp`) plus the txIDs already emitted at the edge; with more rows at one timestamp than `limit`, the next request returned the same rows, all skipped, and the listing ended. Each TronGrid list is now read along its own `meta.fingerprint`, a timestamp's rows are merged from both lists by txID, and a timestamp that does not fit in a page is resumed inside it. The cursor format changes to `{ v: 2, n, s: { tx, trc20 }, t?, g? }` (`n`, the API page size the positions belong to, is kept for the whole listing whatever `limit` later pages ask); a fingerprint the API does not advance ends that list instead of looping, and more than 500 pages of one list in one call fail with `HistoryUnavailableError` instead of shortening the list; a v1 cursor from an earlier version is refused (start the listing again). A page also knows when it is the last one (no cursor). Audit 2026-10-25, #1.5.
