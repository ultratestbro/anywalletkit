The kit and the wallets now read the same amount from a raw send. For `sendTransaction` / `signTransaction` on EVM, Bitcoin, Zcash, Solana, Tron and TON, the amount `confirm` sees comes from `value` (the field the wallet signs). An `amount` field next to `value` that says something else makes the amount unknown (`intent.amount` is undefined), and an `amount` alone is no longer shown as what the transaction pays. `transfer` still reads `amount`. On the wallet side, a value given as a string is signed only when it is at most 300 characters long and has no whitespace, because the policies read no longer string. Longer or padded strings now throw `UnsafeTransactionError` (`wallet-evm` for `value` and the `transfer` amount; `wallet-btc` / `wallet-zcash` with `code: 'malformed-spend'`). Apps that pass bigints, integers or plain decimal / `0x` strings need no change; trim strings before passing them.
