USDT into Tron and TON through the USDT0 Legacy Mesh, from EVM sources only: Ethereum USDT, Arbitrum USDT0 and Celo USD₮ (`0x48065fbBE25f71C9282ddf5e1cD6D6A887483D5e`, by contract — the catalog's Celo `USDT` is a bridged token and is refused) to USDT on `tron:728126428` (eid 30420) and `ton:-239` (eid 30343), one `send` on the chain's `UsdtOFT` with an exact approval to it. The contracts come from docs.usdt0.to (deployments API, Legacy Mesh) and were re-read on-chain on 2026-11-12 (`token()`, `approvalRequired()`, `endpoint()`, `feeBps()` = 3, `peers(30420)` / `peers(30343)` = the Tron / TON OFT); they are checked again before the first quote on a chain and per pair. Limits and fees come from the contract: `quoteOFT` (the pool's credit toward the destination caps the amount, the 0.03 % mesh fee is a `protocol` fee row) and `quoteSend` (the LayerZero fee, sealed with the usual 25 % refunded headroom). The recipient is encoded as the destination OFT reads it — Tron base58check → 20 bytes left-padded, TON raw or `EQ…` / `UQ…` → the account hash on workchain 0 (other workchains and testnet addresses are refused) — and every built send is decoded back against the request before it is returned. Tracking uses the same LayerZero Scan message; a TON delivery completes only when tonapi (`GET /v2/events/{hash}`, new option `tonApiUrl`, default `https://tonapi.io`) shows the USDT jetton paid to the recipient. Tron and TON are destinations only: `supportsChain` is true for them, no pair starts there, and a Tron / TON source is refused with "the USDT0 Legacy Mesh is not wired for a … source here". New exports: the mesh tables and helpers (`USDT0_MESH_SOURCES`, `USDT0_MESH_DESTINATIONS`, `meshRecipientBytes32`, `meshRecipientMatches`, `usdt0VerifyMeshSend`, `usdt0.supportsSourceChain`, …), `TON_API`. `usdt0Pins` now also pins each chain's mesh OFT as call target and spender (Ethereum, Arbitrum, Celo) and `usdt0VerifyQuote` holds a route into Tron / TON to `usdt0VerifyMeshSend`: an app that runs USDT0 behind `remoteProvider` needs this version on the device to accept mesh quotes (an older client refuses them). Existing USDT0 routes and their refusal texts are unchanged; only a Tron / TON source, refused before as "USDT0 is not deployed on this chain", now gets the new "not wired for a … source" text. Note: the engine's native-fee ceiling (0.005 ETH on Ethereum / Arbitrum, 100 CELO on Celo) is below today's LayerZero fee into Tron (≈ 0.0053 ETH, ≈ 170 CELO), so the engine refuses to execute EVM → Tron until that ceiling (`protocol-swap2-core`) is raised; EVM → TON (≈ 0.000056 ETH) fits.
