Honest gas in quotes, and an approval policy per engine and per execution. Without the new options the engine makes the calls 0.17.0 made, checked scenario by scenario (sha256 of every account and provider call) against the published 0.17.0 tarball.

- **`Quote.gasEstimate?: string` / `Quote.gasEstimateSource?: "venue" | "simulated" | "model"`**: the gas the route's main source transaction is expected to use (gas used, not a limit; no execution headroom, no approval). `txRequest.gasLimit` is unchanged and is still what the transaction is sent with and what the native-gas check counts; nothing in execution reads the estimate. Rules (`gasEstimateProblem(quote, sourceChain)`, exported with `GAS_ESTIMATE_SOURCES` from the index and `/validate`): canonical digits (`"0"` or up to 10 digits, no leading zero), both fields or neither, EVM sources only, exactly `"0"` on a `gasless` quote and positive otherwise, at most `txRequest.gasLimit` when there is one. `quoteRejection` refuses a quote that breaks one as malformed (`upstream_unavailable`) and the refusal text names the rule; a swap2 server carries both fields under its seal and refuses to seal a broken one (502).
- **`allowanceReuse?: "exact" | "sufficient"`** (engine config, default `"exact"`; `swap2(options, {allowanceReuse})` overrides it for one execution). `"sufficient"`: an allowance to the route's pinned spender that already covers the input gets no approval and is never lowered, raised or revoked; the swap spends exactly the input from it, and the review plan and the result carry `reusedAllowance: {token, spender, amount, chainId?}` (the allowance as it stands). A smaller or unreadable allowance is approved to exactly the input as before, and after a failure it is put back to its previous value rather than 0 (mainnet USDT: reset to 0 only when an approval is actually sent). Permit2 and CoW (GPv2) make the same calls as in `"exact"`.
- **`revokeUnspentApproval?: boolean`** (default `true`; overridable per execution). `false`: an allowance this execution approved and did not spend (the one re-quote failed, the review was cancelled after a mined approval, a preflight or dry run failed) gets no revoke transaction; the thrown error carries `leftAllowance: {token, spender, amount, chainId}`, read with `leftAllowanceOf(error)`. A typed order whose registration answer was lost is still revoked (it may be live). Permit2 signature-transfer allowances are kept in both modes, as before.
- Invalid option values (`null`, `"SUFFICIENT"`, `0`) throw `Swap2ConfigurationError` before anything is quoted. New exported types: `Swap2AllowanceReuse`, `Swap2Allowance`, `Swap2ExecutionConfig`, `Swap2EngineResult`, `GasEstimateSource`.
- No pin, calldata check, simulation, gas or price check changed. README: "Approvals" (exact vs sufficient, revokeUnspentApproval, leftAllowance, reusedAllowance) and "Gas: `gasEstimate` vs `gasLimit`".
