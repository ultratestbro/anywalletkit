Honest gas in quotes, and an approval policy per engine and per execution. Without the new options the engine makes the calls 0.17.0 made, checked scenario by scenario (sha256 of every account and provider call) against the published 0.17.0 tarball.

- **`Quote.gasEstimate?: string` / `Quote.gasEstimateSource?: "venue" | "simulated" | "model"`**: the gas the route's main source transaction is expected to use (gas used, not a limit; no headroom of the module's own, no approval). `txRequest.gasLimit` is unchanged and is still what the transaction is sent with and what the native-gas check counts; nothing in execution reads the estimate. Rules (`gasEstimateProblem(quote, sourceChain)`, exported with `GAS_ESTIMATE_SOURCES` from the index and `/validate`): canonical digits (`"0"` or up to 10 digits, no leading zero), both fields or neither, EVM sources only, exactly `"0"` on a `gasless` quote and positive otherwise, at most `txRequest.gasLimit` when there is one. `quoteRejection` refuses a quote that breaks one as malformed (`upstream_unavailable`) and the refusal text names the rule; a swap2 server carries both fields under its seal and refuses to seal a broken one (502). Venue figures are passed on as the venues state them; the README's "Gas" section lists how far each module's figure ran from the gas used on 2026-11-28 (0x and KyberSwap about a third above it).
- **`allowanceReuse?: "exact" | "sufficient"`** (engine config, default `"exact"`; `swap2(options, {allowanceReuse})` overrides it for one execution). `"sufficient"`: an allowance to the route's pinned spender that already covers the input gets no approval and is never lowered, raised or revoked; the swap spends exactly the input from it, and the review plan and the result carry `reusedAllowance: {token, spender, amount, chainId?}` (the allowance as it stands). A smaller allowance is approved to exactly the input as before, and after a failure it is put back to its previous value rather than 0 (mainnet USDT: reset to 0 only when an approval is actually sent). An allowance that cannot be read is refused before the review with nothing sent (`Swap2ExecutionError`, `upstream_unavailable`, when the read failed; `Swap2ConfigurationError` when the account has no `getAllowance`), so a user's larger allowance is never overwritten and then zeroed. Permit2 and CoW (GPv2) make the same calls as in `"exact"`. What the mode gives up, stated in the README: under `"exact"` the token contract caps what the swap's call can pull at the input; with a reused larger allowance that cap rests on the provider's own check of its calldata.
- **`revokeUnspentApproval?: boolean`** (default `true`; overridable per execution). `false`: an allowance this execution approved and did not spend (the one re-quote failed, the review was cancelled after a mined approval, a preflight or dry run failed) gets no revoke transaction; the thrown error carries `leftAllowance: {token, spender, amount, chainId}`, read with `leftAllowanceOf(error)`. That error is a new one and the value thrown on the way is never modified: an engine error comes back as a copy of the same class (message, reason, cause and fields kept), anything else (an app's `reviewExecution` error, an account's, a string) as a `Swap2ExecutionError` with the same text and the original as `cause`. A typed order whose registration answer was lost is still revoked (it may be live). Permit2 signature-transfer allowances are kept in both modes, as before.
- **`CrossChainProvider.exactAllowanceOnly?(chain)`** (also on `RemotePins` / `remoteProvider` options): a provider whose spender must not keep an allowance on a chain (an owner that could spend it) holds every execution through it there to the defaults, whatever `allowanceReuse` / `revokeUnspentApproval` say; a throw or any answer but `false` counts as yes, and it is not asked when the options are the defaults. KyberSwap declares it on its generic-build routers.
- Invalid option values (`null`, `"SUFFICIENT"`, `0`) throw `Swap2ConfigurationError` before anything is quoted. New exported types: `Swap2AllowanceReuse`, `Swap2Allowance`, `Swap2ExecutionConfig`, `Swap2EngineResult`, `GasEstimateSource`.
- No pin, calldata check, simulation, gas or price check changed. README: "Approvals" (exact vs sufficient, what sufficient gives up, `exactAllowanceOnly`, revokeUnspentApproval, leftAllowance, reusedAllowance) and "Gas: `gasEstimate` vs `gasLimit`".
