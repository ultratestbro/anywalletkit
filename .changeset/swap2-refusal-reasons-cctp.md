Refusal reasons. CCTP's refusals keep their text and now carry a `reason` (`Swap2RefusalReason`): a catalog USDC that is not Circle's, a pair Circle publishes no fee for, or a finality it does not offer is `unsupported_pair` (a fee answer of another shape is `upstream_unavailable`), an exhausted Fast allowance is `insufficient_liquidity`, an amount below the Fast fee is `amount_too_small`, and a live quote without a recipient is `policy_refused`. In `preflightDeposit`, another deposit target, a TokenMessenger pointing elsewhere or a transmitter of another domain is `vault_mismatch`, a Fast fee that moved above the quoted `maxFee` or is no longer published is `quote_expired`, a malformed intent id is `policy_refused`, and a failed read on the source RPC is `simulation_failed` when the `eth_call` reverted or found no code, else `upstream_unavailable`. Circle API failures that reach the app (preflight, `buildClaim`) carry their status (429 `rate_limited` with `retryAfterMs` from Retry-After, 408 / 425 / 5xx `upstream_unavailable` with `httpStatus`; Circle's API takes no key, so a 401 / 403 is `upstream_unavailable` with `httpStatus`, never `key_rejected`); a network failure or an answer that is not JSON is the same error tagged `upstream_unavailable`, never the caller's own abort. `buildDeposit` without a transaction is `policy_refused`; `buildClaim` refuses an attestation minting on another domain as `recipient_mismatch` and one from another source domain as `policy_refused`. `cctpPins.reasonOf` classifies every text `cctpVerifyQuote` returns (another call target or spender `vault_mismatch`, another domain or mint recipient `recipient_mismatch`, a `maxFee` that leaves less than the minimum `price_check_failed`, a malformed quote `upstream_unavailable`, the rest of the burn's shape `policy_refused`), so a remote stub's refusal carries it. `getQuote`'s bare nulls stay as they were, and a recipient that does not parse stays unclassified.
