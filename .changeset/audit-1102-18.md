NEAR intents now include the account changes made by the actions inside a `SignedDelegate`. Before, a delegate carrying `AddKey(FullAccess)` showed only `accountChanges: ['delegate']` in object form (`sendTransaction` / `signBuilt`) and passed an allowlist that names the own account. Now it reports `['delegate', 'add-key', 'full-access-key']` with `destinationUnknown: true`, the same as a top-level `AddKey`. The base64 borsh reader also no longer stops at a delegate or global-contract action. It reads the delegate's receiver and actions, and any actions after it, so both forms report the same destinations and changes. One visible effect: a borsh transaction that relays a delegate whose only actions are transfers or token calls is now judged by its receivers (`destinationUnknown: false`), as the object form already was. Nothing to change in apps; a confirm screen that lists `accountChanges` now also shows changes made inside a delegated action.
