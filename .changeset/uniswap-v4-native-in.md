Uniswap v4, opt-in: the input is also quoted on the chain's pinned hookless v4 pools and executed through the pinned Universal Router 2.1.2 — directly for a native-coin input, through Uniswap's SwapProxy for a token input; v3 and v4 are ranked together by output. Off by default (`v4: "off"`): every quote is then the v3 quote this module returned before.

- **`v4: "off" | "native-in" | "all"`** (default `"off"`). With `"native-in"`, a native input into an ERC-20 is quoted on v3 and on v4 at the same block, and the best output wins (`v4MinEdgeBps`, default 0: v4 must beat v3 by more than that many bps). With `"all"`, a catalog-token input into a token or into the native coin is ranked the same way. The impact gate of `maxPriceImpactBps` applies to the winner. Every v4 swap carries the same `V4_SWAP([SWAP_EXACT_IN(_SINGLE), SETTLE, TAKE])` input: the exact input is settled (a partial fill reverts `CurrencyNotSettled` instead of leaving input in the router) and the whole output taken to the recipient (`TAKE(address(0), …)` for a native output, paid by the PoolManager). A native input is `UR.execute(0x10, [V4_SWAP], deadline)` with `value = amountIn` and no approval; a token input is `SwapProxy.execute(pinned UR, token, amountIn, 0x10, [V4_SWAP], deadline)` with `value = 0` and `approvalAddress` = the chain's pinned SwapProxy (the engine's exact approve → call → revoke; no core change). Every build is checked by the module's own strict verifier before it is returned.
- **Token input is simulated before any approval.** With the sender known (an execution quote), the provider reads the sender's balance and allowance to the SwapProxy and simulates the approval and the exact swap together before returning the quote: `eth_simulateV1` of `[approve(SwapProxy, amountIn), swap]`; where the RPC does not serve it (Monad), an `eth_call` of the exact swap from the bare account with the token's allowance slot set by `stateDiff` (found with `eth_createAccessList`, verified by reading the allowance back); with no slot that verifies, a 61-byte executor installed as the account's code runs approve → swap through Multicall3. A revert is decoded and mapped; a balance under the input, an unanswered read or nothing simulable refuses — never a silent skip. A read of the check that no endpoint answered after the retries (balance, allowance, access list, slot read-back, the swap's or the executor's `eth_call`) refuses the whole quote with the node's reason (`rate_limited` / `upstream_unavailable`), never the v3 quote in its place: decision 5 (on Monad one `-32007` on the allowance read had returned v3's 1.13 AUSD for 700 USDC, v4 paying 700.08). `providerData.simulated` says how. Live on 2026-11-26, the approve + swap from a funded holder paid exactly the quote on Monad 700 USDC → AUSD / → MON and Base 1,000 USDC → ETH, with the SwapProxy allowance back to 0 and the router's and the SwapProxy's balances unchanged.
- **Pins and checks.** `UNISWAP_V4` pins 19 chains (PoolManager, V4Quoter, StateView, PositionManager, Universal Router `2.1.2` with its per-chain codehash, SwapProxy and its codehash, Permit2, wrapped native), each verified on chain on 2026-11-25; Soneium, Tempo and Zora are left out (not in the catalog). HyperEVM is pinned `quotable: false` (no live pool); on Arc and Celo the native coin is an ERC-20, so native input and output are refused there. Before the first v4 quote on a chain the provider reads `poolManager()` of the router, the quoter and the StateView, the router's codehash and, with `"all"`, the SwapProxy's: a router mismatch turns v4 off on that chain, a SwapProxy mismatch token input only, never v3. On Monad the v4 reads name 30M gas: its RPCs give an `eth_call` 8.1M by default, which starved a two-hop quote inside a Multicall3 aggregate and refused the whole quote.
- **Pools.** Hookless only, with an empty hook allowlist; LP fee ≤ `v4MaxFeePips` (default 100,000 = 10%; it can be lowered, not raised). The candidates come from a generated, pinned per-chain list (`./v4pools`, 1,052 live pools on the 18 quotable catalog v4 chains — every pinned chain but HyperEVM; on Arc and Celo token ↔ token pools only — built by `scripts/build-v4-pools.mjs` from the PoolManagers' `Initialize` logs and gated on chain at one block), read in one Multicall3 `aggregate3` on the pinned StateView, plus the integrator's `v4ExtraPools` (hookless, PoolId recomputed; a bad key throws when the provider is made), plus a union grid of 33 fee/tick-spacing keys for a token the list does not know. A chain is quoted on v4 only with a pool list (shipped, or `v4ExtraPools`). A failed discovery or quote read — an RPC error, a sub-call that fails, a listed pool reading as uninitialized, a quoter call without revert data — refuses the quote (`rate_limited` / `upstream_unavailable`); it never quotes from fewer pools. One exception, a fact rather than a failed read: a quoter call that comes back without revert data even alone in its aggregate is read once more, straight to the V4Quoter with exactly the chain's per-transaction gas bound named (where the module knows it: `KNOWN_TX_GAS_CAP`, else the 32M execution cap of Arbitrum and Robinhood Chain, `KNOWN_EXECUTION_GAS_CAP`), and one that is still empty there needs more gas than any transaction on the chain may have — it is ranked out and counted (`providerData.v4Unexecutable`), never the whole quote refused. On Monad (live, 2026-11-26) a MON/AUSD candidate needing 61.3M quoter gas had made 2,000 AUSD → MON and 20,000 USDC → AUSD unquotable with v4 on (v3 included); now they pay 182,815.6 MON and 20,002.93 AUSD on v4 (v3 alone: 78.65 MON and 1.13 AUSD). A re-read the node does not answer, or answers under a gas cap of its own, still refuses.
- **`uniswapPins`** now lists the Universal Router 2.1.2 as a call target (next to SwapRouter02) on every chain where v4 quotes a native input, and the chain's SwapProxy as a call target and a spender where it quotes a token input; the Universal Router, Permit2 and the PoolManager are never spenders. `uniswapVerifyQuote` dispatches on `tx.to`: a router or SwapProxy call is checked by `uniswapV4VerifyQuote` (UNISWAP-V4-RESEARCH §6.5: selector, strict decode and canonical re-encode in the pinned 2.1.x layout, commands exactly `0x10`, actions exactly swap / SETTLE / TAKE, ≤ 2 hookless pools from the shipped list, exact SETTLE, TAKE to the recipient, `value == amountIn` or 0, deadline, gas cap; for the SwapProxy S1–S14: its pinned address, `router` = the pinned UR, `token` = the request's catalog token, `amount` = the input = the approval, `value` 0); every other call by the v3 check, now also exported as `uniswapV3VerifyQuote`. `reasonOf` classifies the v4 texts too. With `maxPriceImpactBps`, `uniswapV4VerifyQuote` gates on G = max(`priceImpactBps`, `valueLossBps`) over the measures the quote carries (§7.2) and refuses one that carries neither. The pool-provenance check caches PoolIds only for a frozen list of frozen keys (the shipped lists, the pins' own copies); a list the caller can change is read anew on every call. The row-17 gas check uses the provider's own `KNOWN_TX_GAS_CAP` (2²⁴ on Ethereum, OP, BNB, Unichain, World Chain, Base, Ink, Linea and Arc, 2²⁵ on Polygon, 30M on Monad); the verifier's `maxFeePips` is held to 1..100,000 like `v4MaxFeePips` (the 10% cap can be lowered, never raised). **`uniswapPinsWith({v4ExtraPools, clockSkewSeconds})`** builds the same pins with the integrator's own v4 pools (the server's `v4ExtraPools`; their chains get the router / SwapProxy as call targets) and more clock skew on a v4 deadline; `uniswapPins` is `uniswapPinsWith()`. On a chain with v4 pins these pins also refuse a v3 quote paying one of the v4 sinks above (`recipient_mismatch`); `uniswapV3VerifyQuote` is unchanged. `UNISWAP_V3`, `UNISWAP_V4` and `UNISWAP_V4_POOLS` are frozen through their rows (each pool list all the way down): no code in the process can repoint a pinned router or SwapProxy the pins read at call time.
- **Pool provenance across the corridor: `v4RankedPools: "listed" | "extra" | "all"`** (default `"listed"`). An app's pins accept a v4 pool only from the shipped list or the `v4ExtraPools` it pins itself; a pool the server's unlisted-token grid found is neither (and is found per request). So by default the server ranks only shipped-list routes against v3, and returns a route through a grid or an extra pool only when v3 has no route for the pair — an app never loses the v3 quote it had. `"extra"` ranks the server's `v4ExtraPools` too (apps pin the same pools with `uniswapPinsWith` — add a pool to the apps first, then to the server); `"all"` ranks everything (a provider running in the app).
- **List rebuilds never cost an older app its v3 quote: `v4RankedListBlock`.** The lists are rebuilt and released when the watch reports a new live pool, so a server can run a newer list than its apps. `scripts/build-v4-pools.mjs` now reads the previous list back: lists only grow (a pool once listed stays listed, so an older server's routes stay acceptable to newer apps), and every pool a rebuild adds carries `since`, its build block (a chain's first list in a later release: all of them). By default a server ranks against v3 only the pools of the chain's first shipped list (the 0.5.0 lists carry no `since`); a pool with `since` ranks like a grid pool — returned only when v3 has no route. Once every app it serves runs a release whose list for the chain was built at block B or later (`UNISWAP_V4_POOLS[chain].block`), the server sets `v4RankedListBlock: {[chain]: B}`. Tested through `createSwap2Handler` + `remoteProvider` with a server list ⊃ the app's list: v3 stays served.
- **v4 on never costs a pair its v3 route.** A v4 build refused for a reason of the build falls back instead of refusing the quote: the best route's own pools failing its simulated swap, its encoding or the module's own check → the next v4 candidate (at most 3); what every v4 build shares failing (the endpoint cannot simulate the approval and the swap — a method or a state override it does not take, an answer in another shape —, the approval or the token's pull fails) → v3; with no v3 route, the best route's reason refuses. A read that went unanswered is no such fact: it refuses the quote (above). The trade's verdicts still refuse outright: the impact gate, a minimum rounding to 0, the caller's floor, a wallet short of the input, a recipient that cannot take the native coin, and — once v4 is on for the chain, before any read and for every venue — a recipient the chain's v4 pins name as a sink (a router sentinel, the zero address, the Universal Router, SwapProxy, PoolManager, PositionManager, V4Quoter, StateView, Permit2): output paid there is stranded, v3's too. A v4 candidate whose gas need is above the chain's bound is ranked out before ranking (counted in `v4Unexecutable`), so it never displaces a route that can be mined. Live on Monad (fault injection, 2026-11-26): 700 USDC → AUSD on an RPC without access lists or state overrides now quotes v3 (before: refused).
- **`onV4Warning(text, {chainId, reason})`**, the operator's alert (§6.5 row 15, "refuse + alert"): called when the chain's v4 deployment does not match its pins (`vault_mismatch`, naming what — v4 or its token input is off on that chain, v3 untouched) and when a v4 build is set aside for a fallback. Not the caller's `onRefusal`, which is first-wins and dropped when a quote stands. A throw or a rejected promise in it is ignored. Live on Monad: a flipped router code byte or a reverting `poolManager()` now alerts.
- **`v4ExtraPools` is read by one parser** in the provider and in `uniswapPinsWith` (`checkedV4ExtraPools`, in `./v4`): a decimal chain id per key, each once; the provider no longer reads `"0x8f"` as chain 143 or drops `"abc"` silently while the app's pins throw.
- **v4 deadline ≤ 600 s.** A v4 swap's deadline is `min(deadlineSeconds, 600)` ahead (v3 keeps the full `deadlineSeconds`): the bound the pins hold a v4 quote to, with 60 s of clock skew. A server at `deadlineSeconds: 1200` would otherwise have every app refuse its v4 quotes.
- **Preflight** of a v4 quote re-quotes the route on the V4Quoter (a partial fill or an output under the signed minimum refuses it) and `eth_call`s the exact transaction from the quote's sender (`providerData.sender`, set from `QuoteParams.sender`; for a token input after the approval); a revert is decoded through `ExecutionFailed` / `WrappedError` / `UnexpectedRevertBytes` and mapped (`V4TooLittleReceived` → `price_check_failed`, `CurrencyNotSettled` / `NotEnoughLiquidity` → `insufficient_liquidity`, `NativeTransferFailed` → `recipient_mismatch`, an expired deadline → `quote_expired`, a token's `Error(string)` such as `TRANSFER_FROM_FAILED` named in a `simulation_failed`); no answer refuses. A node refusing the dry-run because the sender holds less than it sends (Monad's `-32003 Insufficient funds…`, reth's `OutOfFunds`, geth's `insufficient funds for transfer`) is that answer: `simulation_failed` naming the balance, at once, never "no RPC answered" after the retries.
- **`ownGasEstimate: true`** (for v3 too) on the provider and on the new **`uniswapRemoteProvider({baseUrl, …})`** — the app's stub for a backend: `remoteProvider` with the shipped pins (or `uniswapPinsWith` options), `ownGasEstimate` and `describeActivity`. The engine dry-runs each Uniswap call from the account right before broadcast and sends the account's own estimate, never the quoted limit. A bare `remoteProvider({...uniswapPins})` stub carries no `ownGasEstimate` (core stubs have none) and still sends the backend's limit — use the helper. Monad charges the gas limit, not the gas used, and a v3 quote there carried a 16.3M limit for a swap the account estimates far lower. The quote still carries its bounded `gasLimit` (information, and the gas bound that refuses a swap no block could mine). Two gas facts read live by `verify:live` on 2026-11-26 join the tables: Arc's 2²⁴ per-transaction cap and MegaETH's 100M-gas L1-info deposit.
- **Activity:** a call to the pinned Universal Router's `execute(bytes,bytes[],uint256)` whose commands are exactly `V4_SWAP`, and a call to the pinned SwapProxy's `execute` (`0x2894adf9`) forwarding to that router with exactly `V4_SWAP`, are "Uniswap v4 · <chain>" (recorded public Ethereum SwapProxy swaps); other router and SwapProxy calls stay unclaimed.
- **`providerData`** of a v4 quote: `venue: "v4"`, `route`, `poolFee`, `router`, `currencyIn`, `currencyOut`, `amountIn`, `minOut`, `poolKeys` (JSON), `path`, `priceImpactBps` (and `valueLossBps` when gated), `sender`, and for a token input `simulated`. A v3 quote is unchanged (no `venue`).
- **Exports:** `UNISWAP_V4`, `UniswapV4Deployment`, `V4PoolKey`, `UR_COMMANDS`, `V4_ACTIONS`, `UNISWAP_UR_SELECTORS`, `UNISWAP_SWAP_PROXY_SELECTORS`, `poolIdOf`, `encodeV4Swap`, `uniswapV4VerifyQuote`, `uniswapV4ReasonOf`, `UNISWAP_V4_POOL_KEYS`, `uniswapPinsWith`, `UniswapPinsOptions`, `uniswapRemoteProvider`, `UniswapRemoteOptions`, `UniswapRemoteProvider`; every building block in the new `./v4` subpath; the lists in `./v4pools`.
- **`verify:live`** checks every chain of both tables: v3 linkage; v4 code, linkage and codehashes (the router's, the SwapProxy's and Permit2's — pinned per chain as `permit2Codehash`); a build probe (an unreachable `minHopPriceX36` in the 2.1.x layout must revert `V4TooLittleReceivedPerHopSingle`); a V4Quoter canary; the gas bounds; Monad, Unichain and Base corridors through the provider and the pins (native input, and token input through the SwapProxy: Monad 700 / 20,000 USDC → AUSD and 100 / 2,000 AUSD → MON — the large ones cross candidates past the 30M cap, which must be ranked out —, Base 1,000 USDC → ETH, and Base 1,000 USDC → USDT on v4 alone so the SwapProxy flow runs whichever venue pays more), and the Monad ones in remote mode through `uniswapRemoteProvider`. An unreachable chain fails the run, and a final `Reason:` line names every chain that is not ok (a FAIL line says "linkage drift", never "ok", when its own section found a problem); so does a check that could not run (the build probe is tried on each RPC until one returns revert data; a quotable chain without a canary pinned). **watch.json** watches the five v4 contracts' code on 19 chains, every PoolManager's `owner()` and `protocolFeeController()`, `UNISWAP_V4` against Uniswap's deployments.json, the universal-router / v4-periphery / v4-core releases and (`evm-initialize`, one source per shipped list) new hookless pools — a source's first run (or a re-pointed one) scans from the block its list was built at and reports what it finds against an empty reading, so a pool initialized between the build and the first watch run is not missed. Each source carries a positive control (`canary`: the known `Initialize` log of a listed pool): every run that scans asks the same logs endpoint for that block with the scan's own filter and fails when the log is missing, so an endpoint that answers `[]` for a range it does not index never moves the index past it (BNB Chain's public node did, 2026-11-26). The watch reads the JSON-RPC error a node sends with HTTP 400 / 413 (World Chain's, X Layer's and Ink's public RPCs refuse a wide `eth_getLogs` that way) and cuts the window to the limit the error names; X Layer, World Chain and Ink get the `maxCalls` their public endpoints need for a day, and the CI maps the QuickNode endpoints in a step before the watch runs (they had reached only the later steps).
- **Rollout:** release; then apps bump their pins (a 0.4.x app's `uniswapPins` names SwapRouter02 only and drops a Universal Router or SwapProxy quote — and since a stub gets one quote per pair, that app would lose Uniswap on the pair); only then does a server set `v4: "native-in"`, later `"all"`. With `v4: "off"` the server keeps serving v3 to apps on old pins, and with `"native-in"` token input stays on v3 (tested through `createSwap2Handler` + `remoteProvider`).
- Monad 62,000 MON → AUSD (the cp0x case), recorded at block 125,409,523: v3 alone 1.130999 AUSD (impact 9981, refused at `maxPriceImpactBps: 500`); with `v4: "native-in"` 676.608109 AUSD via MON → USDC (0.05%/10) → AUSD (0.005%/1), G = max(probe 17, spot 23), which passes at 500. Live on 2026-11-26 the same route paid 667.45 AUSD (KyberSwap 669.19 at the time), and the built transaction's `eth_call` paid exactly the quote.
