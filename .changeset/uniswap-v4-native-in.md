Uniswap v4, opt-in: the input is also quoted on the chain's pinned hookless v4 pools and executed through the pinned Universal Router 2.1.2 — directly for a native-coin input, through Uniswap's SwapProxy for a token input; v3 and v4 are ranked together by output. Off by default (`v4: "off"`): every quote is then the v3 quote this module returned before.

- **`v4: "off" | "native-in" | "all"`** (default `"off"`). With `"native-in"`, a native input into an ERC-20 is quoted on v3 and on v4 at the same block, and the best output wins (`v4MinEdgeBps`, default 0: v4 must beat v3 by more than that many bps). With `"all"`, a catalog-token input into a token or into the native coin is ranked the same way. The impact gate of `maxPriceImpactBps` applies to the winner. Every v4 swap carries the same `V4_SWAP([SWAP_EXACT_IN(_SINGLE), SETTLE, TAKE])` input: the exact input is settled (a partial fill reverts `CurrencyNotSettled` instead of leaving input in the router) and the whole output taken to the recipient (`TAKE(address(0), …)` for a native output, paid by the PoolManager). A native input is `UR.execute(0x10, [V4_SWAP], deadline)` with `value = amountIn` and no approval; a token input is `SwapProxy.execute(pinned UR, token, amountIn, 0x10, [V4_SWAP], deadline)` with `value = 0` and `approvalAddress` = the chain's pinned SwapProxy (the engine's exact approve → call → revoke; no core change). Every build is checked by the module's own strict verifier before it is returned.
- **Token input is simulated before any approval.** With the sender known (an execution quote), the provider reads the sender's balance and allowance to the SwapProxy and simulates the approval and the exact swap together before returning the quote: `eth_simulateV1` of `[approve(SwapProxy, amountIn), swap]`; where the RPC does not serve it (Monad), an `eth_call` of the exact swap from the bare account with the token's allowance slot set by `stateDiff` (found with `eth_createAccessList`, verified by reading the allowance back); with no slot that verifies, a 61-byte executor installed as the account's code runs approve → swap through Multicall3. A revert is decoded and mapped; a balance under the input, an unanswered read or nothing simulable refuses — never a silent skip. `providerData.simulated` says how. Live on 2026-11-26, the approve + swap from a funded holder paid exactly the quote on Monad 700 USDC → AUSD / → MON and Base 1,000 USDC → ETH, with the SwapProxy allowance back to 0 and the router's and the SwapProxy's balances unchanged.
- **Pins and checks.** `UNISWAP_V4` pins 19 chains (PoolManager, V4Quoter, StateView, PositionManager, Universal Router `2.1.2` with its per-chain codehash, SwapProxy and its codehash, Permit2, wrapped native), each verified on chain on 2026-11-25; Soneium, Tempo and Zora are left out (not in the catalog). HyperEVM is pinned `quotable: false` (no live pool); on Arc and Celo the native coin is an ERC-20, so native input and output are refused there. Before the first v4 quote on a chain the provider reads `poolManager()` of the router, the quoter and the StateView, the router's codehash and, with `"all"`, the SwapProxy's: a router mismatch turns v4 off on that chain, a SwapProxy mismatch token input only, never v3. On Monad the v4 reads name 30M gas: its RPCs give an `eth_call` 8.1M by default, which starved a two-hop quote inside a Multicall3 aggregate and refused the whole quote.
- **Pools.** Hookless only, with an empty hook allowlist; LP fee ≤ `v4MaxFeePips` (default 100,000 = 10%; it can be lowered, not raised). The candidates come from a generated, pinned per-chain list (`./v4pools`, 856 live pools on 12 chains, built by `scripts/build-v4-pools.mjs` from the PoolManagers' `Initialize` logs and gated on chain at one block), read in one Multicall3 `aggregate3` on the pinned StateView, plus the integrator's `v4ExtraPools` (hookless, PoolId recomputed; a bad key throws when the provider is made), plus a union grid of 33 fee/tick-spacing keys for a token the list does not know. A chain is quoted on v4 only with a pool list (shipped, or `v4ExtraPools`). A failed discovery or quote read — an RPC error, a sub-call that fails, a listed pool reading as uninitialized, a quoter call without revert data — refuses the quote (`rate_limited` / `upstream_unavailable`); it never quotes from fewer pools.
- **`uniswapPins`** now lists the Universal Router 2.1.2 as a call target (next to SwapRouter02) on every chain where v4 quotes a native input, and the chain's SwapProxy as a call target and a spender where it quotes a token input; the Universal Router, Permit2 and the PoolManager are never spenders. `uniswapVerifyQuote` dispatches on `tx.to`: a router or SwapProxy call is checked by `uniswapV4VerifyQuote` (UNISWAP-V4-RESEARCH §6.5: selector, strict decode and canonical re-encode in the pinned 2.1.x layout, commands exactly `0x10`, actions exactly swap / SETTLE / TAKE, ≤ 2 hookless pools from the shipped list, exact SETTLE, TAKE to the recipient, `value == amountIn` or 0, deadline, gas cap; for the SwapProxy S1–S14: its pinned address, `router` = the pinned UR, `token` = the request's catalog token, `amount` = the input = the approval, `value` 0); every other call by the v3 check, now also exported as `uniswapV3VerifyQuote`. `reasonOf` classifies the v4 texts too. A route through a pool only the unlisted-token grid found is not in the shipped list, so an app's pins refuse it.
- **Preflight** of a v4 quote re-quotes the route on the V4Quoter (a partial fill or an output under the signed minimum refuses it) and `eth_call`s the exact transaction from the quote's sender (`providerData.sender`, set from `QuoteParams.sender`; for a token input after the approval); a revert is decoded through `ExecutionFailed` / `WrappedError` / `UnexpectedRevertBytes` and mapped (`V4TooLittleReceived` → `price_check_failed`, `CurrencyNotSettled` / `NotEnoughLiquidity` → `insufficient_liquidity`, `NativeTransferFailed` → `recipient_mismatch`, an expired deadline → `quote_expired`, a token's `Error(string)` such as `TRANSFER_FROM_FAILED` named in a `simulation_failed`); no answer refuses.
- **`ownGasEstimate: true`** (for v3 too): the engine dry-runs each Uniswap call from the account right before broadcast and sends the account's own estimate, never the quoted limit. Monad charges the gas limit, not the gas used, and a v3 quote there carried a 16.3M limit for a swap the account estimates far lower. The quote still carries its bounded `gasLimit` (information, and the gas bound that refuses a swap no block could mine). Two gas facts read live by `verify:live` on 2026-11-26 join the tables: Arc's 2²⁴ per-transaction cap and MegaETH's 100M-gas L1-info deposit.
- **Activity:** a call to the pinned Universal Router's `execute(bytes,bytes[],uint256)` whose commands are exactly `V4_SWAP`, and a call to the pinned SwapProxy's `execute` (`0x2894adf9`) forwarding to that router with exactly `V4_SWAP`, are "Uniswap v4 · <chain>" (recorded public Ethereum SwapProxy swaps); other router and SwapProxy calls stay unclaimed.
- **`providerData`** of a v4 quote: `venue: "v4"`, `route`, `poolFee`, `router`, `currencyIn`, `currencyOut`, `amountIn`, `minOut`, `poolKeys` (JSON), `path`, `priceImpactBps` (and `valueLossBps` when gated), `sender`, and for a token input `simulated`. A v3 quote is unchanged (no `venue`).
- **Exports:** `UNISWAP_V4`, `UniswapV4Deployment`, `V4PoolKey`, `UR_COMMANDS`, `V4_ACTIONS`, `UNISWAP_UR_SELECTORS`, `UNISWAP_SWAP_PROXY_SELECTORS`, `poolIdOf`, `encodeV4Swap`, `uniswapV4VerifyQuote`, `uniswapV4ReasonOf`, `UNISWAP_V4_POOL_KEYS`; every building block in the new `./v4` subpath; the lists in `./v4pools`.
- **`verify:live`** checks every chain of both tables: v3 linkage; v4 code, linkage and codehashes; a build probe (an unreachable `minHopPriceX36` in the 2.1.x layout must revert `V4TooLittleReceivedPerHopSingle`); a V4Quoter canary; the gas bounds; Monad, Unichain and Base corridors through the provider and the pins (native input, and token input through the SwapProxy: Monad 700 USDC → AUSD, Base 1,000 USDC → ETH), and the Monad ones in remote mode. An unreachable chain fails the run, and a final `Reason:` line names every chain that is not ok. **watch.json** watches the five v4 contracts' code on 19 chains, every PoolManager's `owner()` and `protocolFeeController()`, `UNISWAP_V4` against Uniswap's deployments.json, the universal-router / v4-periphery / v4-core releases and (`evm-initialize`) new hookless pools.
- **Rollout:** release; then apps bump their pins (a 0.4.x app's `uniswapPins` names SwapRouter02 only and drops a Universal Router or SwapProxy quote — and since a stub gets one quote per pair, that app would lose Uniswap on the pair); only then does a server set `v4: "native-in"`, later `"all"`. With `v4: "off"` the server keeps serving v3 to apps on old pins, and with `"native-in"` token input stays on v3 (tested through `createSwap2Handler` + `remoteProvider`).
- Monad 62,000 MON → AUSD (the cp0x case), recorded at block 125,409,523: v3 alone 1.130999 AUSD (impact 9981, refused at `maxPriceImpactBps: 500`); with `v4: "native-in"` 676.608109 AUSD via MON → USDC (0.05%/10) → AUSD (0.005%/1), G = max(probe 17, spot 23), which passes at 500. Live on 2026-11-26 the same route paid 667.45 AUSD (KyberSwap 669.19 at the time), and the built transaction's `eth_call` paid exactly the quote.
