With a list of RPC urls (`provider: [a, b, …]`), a broadcast refusal from a later endpoint — "method not found", "transaction underpriced", "insufficient funds" and the like — now throws `BroadcastUnknownError` (`maybeSent: true`, with the transaction's `hash`) when an earlier endpoint was sent the same signed bytes and gave no answer (a timeout, an HTTP error). That earlier endpoint may already have passed the transaction on, so watch the hash instead of signing a new one. An "already known" answer from any endpoint is a success, a refusal when every endpoint answered is still the plain error, and "nonce too low" keeps its existing handling (the hash is looked up first). A single endpoint is unchanged.
