`describeProtocolBehaviour` now also reads `increaseApproval(address,uint256)` (selector `0xd73dd623`, the older StandardToken name) as an approval inside a Tron call, the same as tx-preview and the kit already do, so it is held to the declared-spender and input-amount rules. The `0x` prefix of Tron call data is now matched case-insensitively, and call data that is not hex fails the suite instead of skipping the approval check. Module authors whose Tron fixtures approve via `increaseApproval` must declare that spender and approve exactly the input; fixtures must carry hex call data.
