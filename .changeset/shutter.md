New package (beta): Shutter threshold encryption for wallets and apps. Encrypted mempool: `sendEncryptedTransaction` signs a transaction, encrypts it on the device and submits only the ciphertext to the Sequencer, so it is ordered before anyone can read it (no front-running, no sandwich, no RPC operator sees it); eon key read from the keypers' contracts, the signed transaction checked against the request, refusals before signing (wrong chain, gas over the per-block cap, balance, no eon key, shutdown date), `waitForEncryptedTransaction` (included / submission-failed / replaced / pending); `SHUTTER_GNOSIS_MEMPOOL` until Shutter decommissions it on 2026-11-25. Shutter API: seal a message until a time and open it after (commit-reveal) with Shutter's threshold encryption. Encryption and decryption run on the device in pure TypeScript (BLS12-381 IBE over `@noble/curves`, no WASM or Buffer; byte-compatible with Shutter's published vectors), so it runs in React Native (Hermes). Every identity the API returns is re-derived from prefix and registrant, every decryption key is checked against the eon key by pairing, decryption verifies the ciphertext was not changed, and the ciphertext never leaves the device. Identities register through the API or from the user's own account on Gnosis (`registerCalldata`, `readRegistration`). Verified live on Gnosis mainnet and Chiado (`scripts/verify-live.mjs`).
