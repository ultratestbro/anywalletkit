With a list of providers, a broadcast refusal (`SERVER_BUSY`, `TAPOS_ERROR`, `BLOCK_UNSOLIDIFIED` and the other pre-push codes) from a later provider now throws `BroadcastUnknownError` (`maybeSent: true`, `hash` = the txID) when an earlier provider was sent the same signed bytes and gave no answer (a timeout, a dropped connection, an HTTP error). The earlier provider may already have pushed the transaction, so do not sign a new one for the same payment: watch the hash. A refusal from the first provider tried is still a plain `Error`, and an acceptance or `DUP_TRANSACTION_ERROR` from any provider is still a success.
