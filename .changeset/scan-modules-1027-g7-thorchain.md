The router an EVM-source swap calls and approves must be one of the pinned `THORCHAIN_ROUTERS` (Ethereum, BSC, Avalanche, Base — reported identically on 2026-10-28 by two node operators; `trustedRouters` adds more), and the inbound vault must be reported by a **second THORNode** at quote time and again right before broadcast: a disagreeing or silent second node refuses the swap. Before, the router, spender and vault came from one host and were "confirmed" against that host's own snapshot. **Default hosts are now Liquify's gateway and the IBS team's node** (the documented fallback `thornode.thorchain.network` no longer resolves; Nine Realms is retired). With one custom `nodeUrl`, the default nodes confirm it unless `confirmNodeUrl` names another node; a quote is refused when no second node answers or one disagrees. **Node URLs must be `https:`** (`allowInsecureNodeUrl` for local development). `thorchainPins()` is the app's side of a remote stub: the pinned routers as call targets and spenders, and a `verifyBuild` that confirms the vault in the router call with two nodes and checks the asset, input and memo (destination, refund, limit, affiliate) against the app's own request.

**Breaking:** a quote is refused when no second node confirms the vault (with one configured `nodeUrl`, the default nodes or `confirmNodeUrl`; a local mock needs a second mock in `confirmNodeUrl`); nodes must be https (`allowInsecureNodeUrl`); the default nodes are now Liquify and IBS; a router outside `THORCHAIN_ROUTERS` (extend it with `trustedRouters`) is refused. Upgrade notes: https://docs.anywallet.tech/getting-started/upgrading/.
