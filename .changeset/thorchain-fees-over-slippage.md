THORChain no longer drops out of the route list when its own fees exceed the caller's slippage. `tolerance_bps` sets the memo limit from the pool's feeless spot output, so whenever the liquidity, outbound and affiliate fees came to more than the slippage (500 USDC Base → BTC at 1%: about 1.7%), THORNode refused the quote ("emit asset … less than price limit …"). The provider now makes one retry on the same node with `liquidity_tolerance_bps` set to the caller's slippage. THORNode measures that from the expected output after fees, so the memo limit becomes expected × (1 − slippage): the same floor every other provider quotes and `validQuote` enforces. For destinations with more than 8 decimals the retry asks 1 bp tighter, because the limit is rounded down in 1e8 units. Quotes where the fees fit inside the slippage still take a single request and are unchanged. The memo limit is still read from the node's memo and enforced on-chain, the caller's `minAmountOut` still has to be met, and if THORChain's fees alone (affiliate share included) exceed 5% there is no route, with the reason "THORChain fees X% — too expensive at this amount". A configured affiliate, which used to leave the memo limit above the expected output on accepted quotes, triggers the same retry. Two more cases used to return no quote without saying why and now give a named reason: a memo limit below the slippage floor, and a slippage outside 0–500 bps.
