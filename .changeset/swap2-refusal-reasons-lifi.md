Refusal reasons; every text is unchanged. LI.FI's error answers carry a `reason`: 429 is `rate_limited` (with Retry-After), 401 / 403 `key_rejected`, 408 / 425 / 5xx `upstream_unavailable` with the status unless the body names a passing condition (API code 1005 or a rate-limit message as `rate_limited` with Retry-After, INSUFFICIENT_LIQUIDITY as `insufficient_liquidity`, a halt or maintenance as `chain_halted`), never a pair or route verdict; any other status is decided by the body: its tool codes when they agree (`amount_too_small` for AMOUNT_TOO_LOW and fees above the amount, `amount_too_large`, `insufficient_liquidity`, `no_route`, TOOL_TIMEOUT / RPC_ERROR as `upstream_unavailable`), then its error code and message ("No available quotes" is `no_route`, code 1005 `rate_limited`, code 1010 or an API-key message `key_rejected`), else `no_route`. The module's own 12 s deadline is `upstream_unavailable`; the caller's abort is not classified. A network failure inside that deadline (DNS, a refused connection, TLS) and a 200 answer that is not JSON still return the silent null they always did, so the engine lists them as `lifi: returned no quote` (`no_route`), not `upstream_unavailable`: naming them would add a refusal text the module never gave. The quote checks: an incomplete or malformed answer is `upstream_unavailable`, another recipient or sender `recipient_mismatch`, an untrusted Diamond, call target or spender `vault_mismatch`, the slippage, floor and route-minimum checks `price_check_failed`, the input-side fee cap, another amount or token and transaction shapes the module never signs `policy_refused`, a same-chain route settling through a solver `unsupported_pair`, and Smart Deposits to Solana, the unbound bridges, LI.FI Intents, destination calls and recipients in unread facet data `recipient_unverifiable`; every Diamond calldata and Solana transaction check is classified by what it found. `buildDeposit`'s refusals of a placeholder-priced or transaction-less quote are `policy_refused`. `lifiPins.reasonOf` classifies the texts `lifiVerifyQuote` returns, so a remote stub's "fails this app's own check" carries the reason. A live quote without the sender's address and configuration errors stay unclassified.
