New package: 0x Swap API v2 as a same-chain swap2 provider through the Permit2 flow, exact input on Ethereum, Base, Arbitrum, Optimism, Polygon, Avalanche and BNB Smart Chain, written from the 0x API and the Settler contracts with no 0x package. The key stays on a server (`zeroExProvider`, a getter or a string, sent only as a header; redirects refused, and an answer that came through one anyway or from another origin is not used; under React Native a provider with a key refuses to be built); the app runs `zeroExRemoteProvider`, which re-checks every quote and build on the device, each live quote against exactly the Settler set its own request read. The Settler is read from 0x's on-chain registry over the app's own RPC and must be a CREATE3 deployment of that registry between the deployments the chain table pins as previous and current when pinned (`previousLiveNonce`, `newestLiveNonce`; token sales also up to `ZEROEX_SETTLER_NONCE_MARGIN` newer ones), with contract code at the address — a native-coin sale goes only to the two pinned Settlers; a newer deployment is refused with what to do, and the watch job and `verify:live` report each one; in remote mode the device reads the registry again before the backend's preflight, and a native sale's quote stays valid for at most two minutes; the Permit2 payload is rebuilt on the device (exact input, that Settler as spender, at most ten minutes); the call's target, value, recipient, buy token and minimum are read from the Settler calldata, and its first action must spend exactly that permit (a native sale's must be `NATIVE_CHECK`). Native sales take 0x's Permit2 `allowanceTarget` and approve nothing. Every call goes out with the account's own gas estimate, dry-run first (`ownGasEstimate`). Fees are shown or the quote is refused; an integrator fee nobody asked for, or an excluded source 0x does not know, refuses it. Every refusal has a `Swap2RefusalReason` (`onRefusal`, `zeroExPins.reasonOf`). `zeroExKnownSpenders(provider, chainId)` gives signing policies the Settlers in force as `knownSpenders`. Tested on recorded real answers from all seven chains; `verify:live` checks the registry, the Settlers and Permit2 on chain and, with a key, live corridors.
