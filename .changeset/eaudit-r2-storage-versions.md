New: `storageVersionLedger({ manifest, mark })` and the `versions` option of `macJsonStorage` — rollback protection for signed stores. A MAC alone proves who wrote a value, not that it is the latest: an older signed value copied back verified. With a ledger every signed value carries a version inside its MAC (`STORAGE_VERSION_FIELD`), a signed manifest kept next to the stores lists the latest version of each, and `mark` (session storage) remembers the highest manifest epoch seen. `read()` answers the new state `stale` (and `get()` `null`) for an older signed value put back, for a store deleted after it was written, and for every store when the manifest is missing, unsigned, edited, or older than the mark. A value exactly one version ahead of the manifest is accepted and recorded (a worker killed between the two writes). `ledger.condemn(key)` starts a sealed manifest above everything before it; `ledger.rekey(oldKey, newKey)` goes before the stores' `rekey`, which keep their versions; `acceptUnversioned` lets values signed before the ledger existed through until they are rewritten (off by default). Not detectable, by design of the platform: the whole storage area put back or wiped consistently when there is no mark (across a browser restart or an extension reload). Also new: `NetworksTable.reload()` and `RecipientBook.reload()` drop the in-memory copy, for a storage that only answers once the wallet is unlocked. Nothing changes for code that passes no `versions`; `MacState` gains the member `'stale'`, which only a store with a ledger returns.
