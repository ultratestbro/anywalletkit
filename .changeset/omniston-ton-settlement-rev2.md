TON ↔ EVM orders quote again. Since 2026-11-10 Omniston names a new TON Escrow Minter, `EQDybO88l2lrrAmALRUqpmgEE_tuxk510F4Yd4xjbQZxC9IA` (rev2), in every TON ↔ EVM quote, and the SDK refused them all ("untrusted TON settlement contract" / "untrusted ton:-239 settlement contract"). `AUDITED_OMNISTON_SETTLEMENT_CONTRACTS["ton:-239"]` now lists it next to `EQAbWJ3Y1HgIIvcMq1prG1anlDC0T3cZlAU7luPT6LmTpmrZ` (rev1), which stays trusted while orders on it settle and refund. `DEFAULT_OMNISTON_TON_CODE_HASHES.position` adds `eb503578…`, the code of the positions rev2 deploys for EVM → TON orders, so the check before the secret is disclosed accepts them; the two changes ship together. Every other pin is unchanged (escrow, execution, authority key, output escrow, position stages). `OMNISTON_ESCROWS` lists both minters, so `describeActivity` tags TON → EVM orders on rev2 as `bridge`. The rev2 minter was reviewed read-only: same admin as rev1 and as the STON.fi DEX v2 routers, no upgrade done or pending, and its code differs from rev1 only by added restrictions (an escrow-code whitelist of the pinned codes). No API change. If your server sets its own settlement table (for example from an `OMNISTON_TRUSTED_SETTLEMENT_CONTRACTS` env), add the rev2 address there too: such a table replaces the built-in one.
