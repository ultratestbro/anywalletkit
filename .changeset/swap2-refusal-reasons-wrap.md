Refusal reasons. The wrap venue's refusals keep their text and now carry a `reason` (`Swap2RefusalReason`), as `onRefusal`'s second argument and on the thrown errors (still plain `Error`s with the same message). In `getQuote`, flexible amounts, another chain, a chain without a wrapped native or an RPC, an unknown token and any pair but native ↔ wrapped are `unsupported_pair`; a recipient other than the sender (WETH9 pays `msg.sender`) is `recipient_mismatch`; a zero amount is `amount_too_small`; a floor above the 1:1 output is `price_check_failed`; a pinned wrapper whose on-chain symbol or decimals differ is `vault_mismatch`. When no RPC answers, the refusal takes the last endpoint's status (429 `rate_limited` with `retryAfterMs` from Retry-After, 401 / 403 `key_rejected`, any other `upstream_unavailable` with `httpStatus`); a node's throttling answer (JSON-RPC code -32005 "limit exceeded" or 429) is `rate_limited`; a network failure, the module's own timeout, malformed JSON, any other JSON-RPC error and an undecodable answer are `upstream_unavailable`. `buildDeposit` on a quote without a transaction is `policy_refused`. `wrapPins.reasonOf` classifies every text `wrapVerifyQuote` returns, so a remote stub's refusal carries it: a route, pair or token this venue does not serve `unsupported_pair`, a recipient other than the sender `recipient_mismatch`, another contract or any approval `vault_mismatch`, amounts that are not integers `upstream_unavailable`, and any other call, chain, amount or value `policy_refused`. A quote whose `sourceAmount` is not an integer or whose call target is not an address still makes the check throw; that error's text is classified `upstream_unavailable` the same way. A non-integer `amountIn` stays unclassified.
