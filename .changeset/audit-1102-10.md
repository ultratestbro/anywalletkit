After a successful broadcast, `sendTransaction` / `transfer` now always return the hash of the bytes the account signed (EVM: keccak256 of the signed transaction; Tron: the signed `txID`), not the id the RPC node echoes back. An honest node echoes the same value, so nothing changes in practice; a buggy or hostile node can no longer point the app's tracking and receipt at a different transaction.
