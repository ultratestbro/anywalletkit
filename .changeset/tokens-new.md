New package: tokens users add by address, at their own risk. `inspectToken(account, address)` reads the token from the chain through the account's `getTokenInfo` (EVM contracts, Solana mints including Token-2022) and returns `{ listed }` for a catalog token or `{ info, assessment, token }`. `assessToken` lists every warning, worst first: `impersonation` when the symbol reads as a catalog token of the same chain or a native coin / major stablecoin anywhere (Cyrillic and Greek look-alikes, `$`, `₮`, fullwidth and invisible characters folded), issuer powers (`permanent-delegate`, `transfer-hook`, `non-transferable` as danger; `upgradeable`, mint / freeze authority, transfer fee, default-frozen, pausable as caution) and `unlisted` always. `TokensTable` keeps the list over any JSON storage (queued writes, a failed read stays unloaded, catalog tokens and malformed entries refused). `swapSource(token)` gives the swap options for engines with `allowUnlistedTokens`.
