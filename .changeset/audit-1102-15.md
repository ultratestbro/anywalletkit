A transaction's `value` is now accepted only as a bigint, a whole number, or a string that `BigInt()` reads (decimal or `0x…`), which are the shapes the kit's policies read as the amount. Before, the wallets coerced other shapes that the policies could not read. `wallet-evm` read a one-element list or an object with `valueOf` through `BigInt()`. `wallet-btc` and `wallet-zcash` also rounded `'1e5'`, `1.4` or `[100000]` into sats or zatoshis. In each case `confirm` saw no amount while the full value was signed. These shapes now throw `UnsafeTransactionError` (BTC/Zcash: `code: 'malformed-spend'`). Apps that pass values in base units as bigints, integers or integer strings need no change. An app that passes a fractional number of sats, or a string like `'1e5'`, must round or convert it before sending. BTC `feeRate` is still rounded as before.
