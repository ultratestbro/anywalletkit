`wallet-solana` now exports `serializedGuardFromExecution(expect, extra?)` (and the `SerializedExecutionInput` type): it turns the expectation the swap2 engine hands an account's `sendSerializedTransaction(serializedTx, expect)` hook into the guard for `sendSerialized` / `checkSerialized`, carrying every field — `maxValueOut` → `maxLamportsOut`, `tokenIn`, `source` → `maxTokenOut`, and `bridgeOut` with its reviewed `destToken`, `minAmountOut` (as a bigint, only with `destDecimals`) and `slippageBps`. `extra` adds guard options such as a program allowlist. The engine sets `bridgeOut` on every cross-chain serialized leg; a guard without it still behaves as before (SOL ceiling and token bounds only), so an adapter that drops it leaves a bridge's recipient unchecked.

What to do: replace a hand-written mapping with the helper, for example in an account adapter:

```ts
sendSerializedTransaction: (tx, expect) => solanaAccount.sendSerialized(tx, serializedGuardFromExecution(expect))
```
