THORChain quotes are no longer refused because the inbound vault rotated or the confirming node is a few blocks behind. THORChain's inbound address moves among its active asgard vaults every few minutes, and public nodes reachable from a browser trailed the quoting node by ~25–28 blocks on 2026-11-12, so requiring the confirming node's current inbound to equal the quoted vault refused most quotes ("a second node reports another inbound vault — refused until they agree"). A confirming node now also confirms the source chain's address of a vault it lists as `ActiveVault` in `/thorchain/vaults/asgard` whose mimir does not flag it `CompromisedVault` or `SolvencyHaltVault` (THORNode leaves those out of inbound election and does not credit an inbound to a compromised vault); a `RetiringVault` or any other status never confirms. The router check, halts (now also the destination chain on the confirming node), memo, expiry, minimums and the quote node's own inbound binding are unchanged, and the calldata must still pay exactly the quoted vault. New options: `confirmMaxLagBlocks` (default 50) skips a confirming node that trails the quoting node's `/thorchain/lastblock` height by more, and `confirmTimeoutMs` (default 2500) bounds each confirming node inside the quote's 8 s budget (AbortController + setTimeout, no AbortSignal.timeout). Confirming reads are `GET` on four fixed paths with no query string and no cache option, exported as `THORNODE_CONFIRM_PATHS`: a proxy in front of a confirming node must pass `/thorchain/lastblock`, `/thorchain/vaults/asgard` and `/thorchain/mimir` besides `/thorchain/inbound_addresses`, or it is skipped for the next node. Existing refusal texts are unchanged; new ones name a lagging set of nodes, a non-active vault status and a mimir flag.
