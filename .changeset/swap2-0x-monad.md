Monad (`eip155:143`) joins the default chain table: Settler registry `0x00000000000004533Fe15556B1E086BB1A72cEae`, taker Settlers 12 `0xF16D1df42E368e4dd873b1f92ED0670FF4c987eB` (current) and 11 `0x031D28683fFc9936903a31670bC618b8Bc9b65dD` (previous), canonical Permit2, WMON `0x3bd359C1119dA7Da1D913D1C4D2B7c461115433A`; watched like the other chains and covered by `verify:live`. Every chain's `prev(2)` is now watched too, and the Settler in force (`ownerOf(2)`) is a severity-high watch source: a new deployment on a pinned chain refuses native-coin sales from that day. Apps that passed Monad through `chains` can drop the override; Monad swaps are now labelled in activity history. Monad bills the gas limit, not the gas used: every 0x call already goes out with the account's own estimate, and a quote whose padded gas limit (0x's gas × 1.2 + 20,000) comes to more than 6,000,000 — 0x asking for more than 4,983,334 — is refused. On Monad that cap is a practical ceiling: swaps there take 7–10 times the gas of the same swap on Base, and in live quotes on 2026-11-26 0x sales of MON were refused from about $10,000 (1,000,000 MON asked for 5,024,738), with sales from about $1,600 up at 82–93 % of the cap.

Activity labelling reads the chain table the provider was built with (`zeroExProvider` / `zeroExRemoteProvider`, `chains`), not only the defaults, so a chain added or re-pinned through `chains` is labelled too; `describeZeroExActivity(tx, ctx, chains?)` takes the table as an optional third argument.

`verify:live`: a chain no RPC answers fails the run (it printed `ok — no RPC for …` before), Monad has a public endpoint, `RPC_<chainId>` may list a fallback (`url,url`), a read the RPC did not answer (a JSON-RPC error that is not a revert — a revert is code 3 or "execution reverted…", so neither a rate limit nor a gateway's "request reverted by gateway" is one —, an answer for another chain, or no code at the pinned registry, an RPC with no state) is retried on the next endpoint instead of being read as the registry's word, a registry that names no Settler is read a second time before it is reported, a failed read prints its JSON-RPC code and a fixed class rather than the RPC's own message, and a failed run ends with `Severity: high` (when a sale through the Settler in force is refused today: what is refused and why, per chain; on a deployment day 0x keeps quoting the previous Settler for a while — on 2026-11-26 it quoted prev(2) on all eight chains — and a native-coin sale to it still passes, which the line says) and a `Reason:` line that names every chain that is not ok (`Reason: NEW on 1, 8453; unreachable on 143`). With `ZEROEX_API_KEY` it also quotes Monad MON → AUSD (100 MON, native) and USDC → MON (Permit2). No runtime check changed. Monad has no recorded 0x answers yet (they need a 0x API key): `fixtures/pin-eras.json` lists it as unrecorded, and a test holds it to being new in the pin era in force, so its first recordings must land before the next pin raise.
