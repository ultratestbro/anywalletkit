`sendTransaction`, `signTransaction` and `quoteSendTransaction` now check that the transaction is one plain object before doing anything else. Before, a list that also carried named fields (`Object.assign([call], { to, value, gasLimit })`) could still be sent on an account with `simulate: false` when the caller set `gasLimit`, or quoted, because the send path copied it into a plain object before the check ran. It now throws `UnsafeTransactionError` on every path, without touching the RPC. Nothing to change in apps that pass `{ to, value, data }` objects.
