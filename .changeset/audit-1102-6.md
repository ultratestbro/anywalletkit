When `provider` is an EIP-1193 object, an `eth_sendRawTransaction` error without a JSON-RPC code (viem reports it as `UnknownRpcError`, code -1), an error whose `code` is an HTTP status such as 502, or an `HttpRequestError` / `TimeoutError` thrown by another copy of viem inside the provider now ends as `BroadcastUnknownError` (`maybeSent: true`) unless its text carries a node's exact refusal words ("nonce too low", "insufficient funds for gas", "transaction underpriced", …). Before, any such text that mentioned "nonce" or "tip" read as a definite refusal. Errors with a JSON-RPC code (-32000 and the like) are read as before. Treat `BroadcastUnknownError` like a timeout: watch the hash, do not sign again.
