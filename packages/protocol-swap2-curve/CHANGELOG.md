# @anywalletkit/protocol-swap2-curve

## 0.1.4

### Patch Changes

- 9bab252: Refusal reasons. Every refusal keeps its text; `getQuote` passes the classification to `onRefusal` as its second
  argument, and the errors thrown by `preflightDeposit`, `buildDeposit` and the JSON-RPC client carry it (`refusalOf`).
  Flexible amounts, cross-chain requests, a chain without router, allowlist or RPC, an uncatalogued or non-address token,
  the router's 0xEeee sentinel, the same token in and out and a wrap `unsupported_pair`; a recipient that is not an EVM
  address `recipient_mismatch`; a zero amount and a minimum that rounds to 0 `amount_too_small`; no allowlisted route, or
  none that quotes the amount, `no_route`; the caller's floor `price_check_failed`; a router off its pinned code or
  version `vault_mismatch`; a quote without a transaction `policy_refused`. When no RPC answers, the refusal takes the last
  endpoint's reason (HTTP 429 `rate_limited` with Retry-After, a JSON-RPC rate-limit error `rate_limited`, 401 / 403
  `key_rejected`, any other status `upstream_unavailable` with `httpStatus`), else `upstream_unavailable` for a network
  failure, a timeout, an answer that is not JSON or leaves calls unanswered. At preflight (and in `curveRemotePins`
  `verifyBuild`): the price moved under the minimum, and a remote build's output or minimum off the fresh `get_dy`,
  `price_check_failed`; `get_dy` reverting `simulation_failed`; another call target, approval, pool code or coin
  `vault_mismatch`; an unreadable pool `upstream_unavailable`; other bytes, value or chain `policy_refused`.
  `checkRoute`'s texts: a denied or unlisted pool, a wrap or ERC-4626 hop off the pinned contract `vault_mismatch`; a
  route ending at another token `price_check_failed`; every other route shape `policy_refused`. `curvePins` and
  `curveRemotePins` gain `reasonOf` for the texts `curveVerifyQuote` and `verifyBuild` return (also `unsupported_pair`,
  `recipient_mismatch`, and `price_check_failed` for a minimum of 0 or off the quote), so a remote stub's "fails this
  app's own check" error carries the reason. The `defaultSlippageBps` option check, an invalid amount or slippage, a chain
  with no RPC endpoint configured and the caller's own abort stay unclassified.

## 0.1.1

### Patch Changes

- 5fbf573: Curve preflight no longer refuses a sound swap over a busy RPC or an odd pool return.
  
  - **A rate-limited batch is an RPC failure, not a pool off its pin.** QuickNode answers a burst with HTTP 200 and a `-32007 "50/second request limit reached"` error in each element; those were read as missing answers and the preflight said "pool X is not the pinned code" or "does not report its pinned coin k". Now only a revert (code 3, or an execution error such as "execution reverted") counts as an answer; any other element error, or a call left unanswered, sends the batch to the next endpoint, once more after a 1 s pause when the last refusal was for the request rate, and then refuses as `no RPC answered on chain N`. A pool whose code cannot be read says `could not read pool X over RPC`.
  - **A return longer than one ABI word is read by its first word.** The Liquity factory metapool (`0xEd27…F0cA`, Ethereum) answers `coins(i)` with 4096 bytes, so every route through it was refused at preflight although the allowlist admitted it. Addresses now need only their upper 12 bytes zero in the first word (a recorded live return is a test fixture).
  - `curveOnChain(…).checkPools(chainId, pools)` runs the preflight's pool check without a route; `scripts/verify-live.mjs` puts every allowlisted pool through it, so a pool the generator admits and the runtime refuses fails the live check.

## 0.1.0

### Minor Changes

- 214771a: New package: Curve same-chain swaps as a swap2 provider, straight from the contracts — Router NG `get_dy` quotes and `exchange` execution on 18 EVM chains (Ethereum v1.2, Arbitrum, Base, OP Mainnet, Polygon, Gnosis, Avalanche, BNB Chain on the `[5][5]` routers; Sonic, Unichain, HyperEVM, Mantle, Monad, Plasma, Robinhood Chain, Ink, X Layer, Plume on the `[4][5]` routers). No API on the money path, no key, no fee.
  
  - **Routes only through a curated, pinned pool allowlist** (one or two pools), plus the router's wrap hop through the pinned wrapped native and, on Ethereum's v1.2 router only, the crvUSD ↔ scrvUSD ERC-4626 hop. The allowlist (`CURVE_POOLS`, `src/pools/<chainId>.ts`) is generated by `scripts/build-allowlist.mjs` from Curve's pool lists and checked on-chain at one block (coins, code hash, registration, decimals, balances, `get_dy`, stable-ng asset types and rate oracles, TVL anchored on catalog coins, age): 71 pools on Ethereum (52), Base (5), Arbitrum (4), Monad (3), Gnosis, Plasma, X Layer (2 each) and OP Mainnet (1); a chain without pools is not offered.
  - **Route rules**: between two pools a route passes only through a swap2-assets catalog token, the native coin or the pinned wrapped native (a pool's other coins may be anything the allowlist admitted); `exchange_underlying` only on a metapool whose base pool is allowlisted too (never on a lending pool); `[4][5]` routers only drive NG pool types 10/20/30. Refused whatever a list says: the registered fake-USDT pool, the four pools drained in 2023 (alETH, pETH, msETH, CRV/ETH), the Iron Bank cy-pool and Polygon amWBTC/renBTC.
  - **No gas limit** on the router call: the wallet estimates the exact call at broadcast (a per-step formula ran some routes out of gas and overcharged on Monad, where the limit is what is paid).
  - **Pins per chain**: router address, ABI family, `version()` and runtime code hash (checked once per chain before quoting), wrapped native; the AddressProvider is only compared and a different id 2 only warned about, never used.
  - **Execution**: the explicit-receiver `exchange` paying the recipient, `min_dy` never 0 (auto slippage from swap2-core by default), exact approval to the pinned router only, `value` exactly the input for a native source. Router NG has no deadline, so the quote's lifetime is enforced by the engine (3 min).
  - **Preflight**: byte-equality with the sealed quote, the route re-checked, each hop pool's code and coins re-read and a fresh `get_dy` at or above the minimum before broadcast (the immutable router's code hash and version are checked once per chain per process, not again here).
  - `curvePins` / `curveVerifyQuote` (synchronous, from the shipped tables) and `curveRemotePins({rpcUrls, defaultSlippageBps?})` for `remoteProvider`, whose on-chain `verifyBuild` also holds a remote quote's output and `min_dy` to the fresh `get_dy` within the slippage (the request's, the backend's fixed default, or auto slippage re-derived on the device), so a backend cannot name `min_dy = 1`; one intent id per quote (`curve:<chainId>:<nonce>`); `describeCurveActivity` (both ABI families, Ethereum's older v1.1 / v1.0 routers for history, a receiver other than the owner said out loud); `curveKnownContracts` for tx-preview; `CurveSwap2Protocol` standalone.
  - Checked live (read-only, `scripts/verify-live.mjs`): every router's code hash, version, immutables and ABI family on all 18 chains; quotes on every chain with pools simulated with `eth_call` as a funded dummy wallet; on the chains without pools the provider is not offered and a quote refuses by name. The module watch reads every router's `version()`, every AddressProvider's id 2 and deployments.json.
