One interface covers same-chain swaps and cross-chain transfers. A **router** asks every
provider you install in parallel, checks each quote the same way, ranks the routes and
executes the one you choose. Snippets on this page come from [`examples/swap`](https://github.com/ultratestbro/anywalletkit/tree/main/examples/swap), which our CI
typechecks and tests.

## Install

```sh
npm install @anywalletkit/protocol-swap2-router \
  @anywalletkit/protocol-swap2-lifi @anywalletkit/protocol-swap2-near-intents \
  @anywalletkit/protocol-swap2-thorchain @anywalletkit/protocol-swap2-chainflip \
  @anywalletkit/protocol-swap2-cctp \
  @anywalletkit/protocol-swap2-usdt0 \
  @anywalletkit/protocol-swap2-uniswap @anywalletkit/protocol-swap2-wrap \
  @anywalletkit/protocol-swap2-jupiter
```

The router bundles no provider. Only the providers you install and pass in end up in your
app, and each provider also works on its own without the router.

### Curve

`@anywalletkit/protocol-swap2-curve` swaps on Curve Router NG straight from the contracts: the
router's own `get_dy` prices each candidate route and its explicit-receiver `exchange` executes the
best one, paying only the recipient and reverting under the minimum (never 0). Routes cross one or
two pools, and only pools from a curated allowlist the package pins — generated by
`scripts/build-allowlist.mjs`, checked on-chain (code hash, coins, TVL, age) and reviewed in the
diff. Between two pools a route only passes through a catalog token, the native coin or the pinned
wrapped native; the registered fake-USDT pool and the pools drained in 2023 are refused whatever a
list says. The router's code hash and version are checked before the first quote on a chain, and
right before broadcast the module re-checks the sealed call, each pool's code and coins, and a fresh
`get_dy` against the minimum. On Ethereum the v1.2 router also swaps crvUSD ↔ scrvUSD in one step.

```ts
import { curveProvider } from '@anywalletkit/protocol-swap2-curve'

const curve = curveProvider({ rpcUrls: { 1: ['https://eth.example/rpc'], 42161: ['https://arb.example/rpc'] } })
```

Routers are pinned on 18 EVM chains; a chain is offered only where the allowlist has pools and you
pass an RPC (Ethereum, Arbitrum, Base, OP Mainnet, Gnosis, Monad, Plasma and X Layer today).

- **MEV on Ethereum.** The minimum caps what a sandwich can take at your slippage; it does not stop
  one from taking up to that. Keep the default small slippage on stable pairs and send Ethereum
  swaps through an MEV-protected RPC (a private transaction relay) where you can.
- **No gas limit in the quote.** The router call carries none: the wallet estimates the exact call
  (with headroom) right before broadcast, after any approval. A per-step formula ran some routes out
  of gas and overcharged where the limit is what you pay (Monad).
- **Behind a backend:** `remoteProvider({ name: 'curve', baseUrl, ...curvePins })` checks the call
  on the device; `...curveRemotePins({ rpcUrls })` also checks the build on chain and holds the
  backend's output and minimum to a fresh `get_dy` within the slippage, so the minimum is the
  device's own. If the backend provider sets `defaultSlippageBps`, pass the same value here.

The router is bound to one account: the source of the swap. Its chain is the source chain.

## 3. Describe the swap

<Snippet file="swap/src/swap.ts" region="options" />

- `fromToken`: a token on the **source** chain, as its contract address or a catalog symbol
  (`'USDC'`, `'ETH'`).
- `toToken`: the token on the **destination** chain, as that chain's own id: a contract
  address, a Solana mint or a TON jetton master. A symbol that does not exist in the catalog
  of the destination chain leads to "no route".
- Tokens outside the catalog (the user's own) need `allowUnlistedTokens` on the engine: see
  [Custom tokens](/guides/tokens/#swap-it).
- Omit `toChain` for a same-chain swap.
- Amounts are `bigint` in base units. Use `toTokenAmount` instead of `fromTokenAmount` for
  exact-output swaps.

## 4. Quote

<Snippet file="swap/src/swap.ts" region="quote" />

Show the user `toTokenAmountMin`, not `toTokenAmount`: it is what the route guarantees.

## 5. Let the user pick a route

<Snippet file="swap/src/swap.ts" region="routes" />

Routes come back ranked by value. Two of them are tagged:

- **`best`**: the highest value. Routes within 0.2% of each other count as the same price;
  inside that band the faster and more reliable route wins.
- **`fastest`**: the lowest estimated time.

For a real USDC Ethereum → Base quote on 100 USDC, this returned four routes: CCTP
tagged `best` (99.989 USDC guaranteed, ~3 minutes), LI.FI tagged `fastest` (99.735 USDC,
seconds), then NEAR Intents and THORChain. For 25 USDT from Ethereum to USDT0 on Arbitrum,
USDT0 came out `best` (exactly 25 guaranteed, ~17 minutes) and LI.FI `fastest`.

Pass `valueUsd: usdValue(prices)` to the router to rank on net USD value. Gas and native
bridge fees are then subtracted.

## 6. Execute

<Snippet file="swap/src/swap.ts" region="execute" />

Before anything is signed, the router fetches a live quote from the chosen provider and
checks it against what you showed:

- the output is not below your `minAmountOut`;
- the recipient, amounts and chains match the request;
- the transaction sends exactly the quoted amount, and any transfer or approval inside it
  names only your account, the quoted deposit address or the declared spender;
- aggregator calls go only to that provider's audited contracts.

A route that fails any check is refused, and nothing is sent. ERC-20 approvals are for the
exact amount, never unlimited, and are revoked again if the swap fails after approving. On
Ethereum, USDT is reset to zero first, as that token requires.

## 7. Track delivery

A cross-chain swap finishes on another chain, minutes later. Poll its status with the id
returned by `swap2()`:

<Snippet file="swap/src/swap.ts" region="status" />

| Status | Meaning |
|---|---|
| `pending` | In flight |
| `action-required` | Two-phase route (CCTP): the user must claim on the destination chain |
| `completed` | Delivered |
| `refund-pending` / `refunded` | The provider is returning / has returned the funds |
| `failed`, `expired`, `cancelled`, `partial` | Final, not delivered in full |

The id is a string (`awk1.<provider>.…`). Store it with the user's activity: it is all you
need to resume tracking after an app restart.

## 8. Handle errors

<Snippet file="swap/src/swap.ts" region="errors" />

:::danger[Never retry a `Swap2MaybeSentError`]
The source transaction may already be on its way. Retrying can send the money twice.
Track the id or hash instead.
:::

## Fee caps

`maxNetworkFeeBps` and `maxProtocolFeeBps` (basis points of the input) refuse routes whose
**itemized** fees are above the cap. The check is fail-closed: a route whose provider does
not itemize its fees is refused whenever a cap is set. With caps on, the USDC example above
keeps only the CCTP route. To protect the user without losing routes, compare the
guaranteed output (`toTokenAmountMin`) instead.
