Earn modules come in two shapes, and every module of a shape has the same methods:

| Interface | Modules | Flow |
|---|---|---|
| `StakingProtocol` | Lido (ETH), SSV Network, Tonstakers (TON), SPL stake pools (Jito on Solana), native SOL staking, native MON staking (Monad), native NEAR staking, liquid NEAR staking (LiNEAR, rNEAR) | Stake → request a withdrawal → wait for the queue → claim |
| `LendingProtocol` | Aave v3, Morpho, Mellow, Kamino, Curve (Savings crvUSD) | Supply / withdraw, and on markets that allow it, borrow / repay |

This page uses Lido and Aave on Ethereum. The other modules work the same way, with
different packages and chains (see [Packages](/getting-started/packages/#earn)). Snippets
come from [`examples/earn`](https://github.com/ultratestbro/anywalletkit/tree/main/examples/earn), which our CI typechecks and tests.

```sh
npm install @anywalletkit/protocol-staking-lido-evm @anywalletkit/protocol-lending-aave-evm
```

### Unstake: two phases

Staked funds do not come back in one transaction. A withdrawal request joins the protocol's
queue, finalizes later (hours to days, depending on the protocol), and only then can be
claimed. The interface names the queue instead of pretending `withdraw()` returns money:

<Snippet file="earn/src/earn.ts" region="unstake" />

Show `pendingAmount` as "unstaking" and `claimableAmount` with a **Claim** button. Check
the queue when the screen opens; there is nothing to watch in between.

## Lending

### Supply and withdraw

<Snippet file="earn/src/earn.ts" region="supply" />

Tokens are contract addresses; `'native'` supplies the chain's coin (ETH) through Aave's
gateway. Where the token supports EIP-2612, the module signs a permit instead of sending a
separate approval transaction. `amount: 'max'` withdraws or repays everything, interest
included.

### Position and health

<Snippet file="earn/src/earn.ts" region="lending-position" />

With debt, keep an eye on `healthFactor`: below `1.0` the position can be liquidated. Show
it on every borrow and withdraw screen, and warn well before it gets close (for example
under `1.5`).

## Native SOL staking

`@anywalletkit/protocol-staking-native-solana` delegates SOL straight to validators through
Solana's Stake program: no pool, no token. Your app decides which validators it offers; the
module has no default list and refuses to start without one.

```sh
npm install @anywalletkit/protocol-staking-native-solana @anywalletkit/wallet-solana
```

### Choose the validators

<Snippet file="earn/src/native-solana.ts" region="native-setup" />

Each stake goes to a validator from this list (or any voting validator with
`validators: 'any'`, when your users pick from the whole cluster). Before every delegation the
module reads the validator live and refuses it when it is delinquent or its commission is above
`maxCommission` (10 % unless you set it). `enrich` can attach an explorer's APR or a logo to each
validator; the on-chain checks do not depend on it.

### Stake

<Snippet file="earn/src/native-solana.ts" region="native-stake" />

A stake is one transaction: a new stake account at an address derived from the wallet (seed
`stake:<i>`), initialized with the wallet as its only authority and delegated. Only the wallet
signs, and the position can be rebuilt from the wallet address alone. The minimum is 1 SOL; the
account also holds about 0.0017 SOL of rent, which comes back on withdrawal. The stake starts
earning from the next epoch boundary (an epoch is about two days).

### Position

<Snippet file="earn/src/native-solana.ts" region="native-position" />

`status` is computed from the StakeHistory sysvar the way the Stake program computes it:
`activating`, `active`, `deactivating` or `inactive`, with `readyEpoch` / `readyAt` while it
changes. Rewards compound into each account at every epoch boundary; `getRewards()` lists them
per epoch.

### Unstake and claim

<Snippet file="earn/src/native-solana.ts" region="native-unstake" />

Unstaking deactivates whole accounts and, for a partial amount, splits it off one account into
a new one first; both parts must keep the 1 SOL minimum. The SOL can be withdrawn after the
cool-down (the next epoch boundary). A stake deactivated in the epoch it was made is free at
once, and `delegate({ account })` in the same epoch undoes an unstake. `merge` joins two
compatible accounts on the same validator.

:::note[Allowlist policies]
A Solana `allowlist` checks each Stake instruction by whom it pays or empowers. Allow the
wallet's own address (staker, withdrawer, withdrawal recipient), the stake accounts
(`getStakeAccountAddress(i)`) and the vote accounts of the validators you list, or the kit
refuses staking writes. Allowlisting the Stake program itself opens nothing.
:::

## Native MON staking

`@anywalletkit/protocol-staking-native-monad` delegates MON straight to Monad validators through
the staking precompile (`0x…1000`): no pool, no token. Your app decides which validator ids it
offers; the module has no default list and refuses to start without one.

```sh
npm install @anywalletkit/protocol-staking-native-monad @anywalletkit/wallet-evm
```

### Choose the validators

<Snippet file="earn/src/native-monad.ts" region="monad-setup" />

`validators: 'any'` lets users pick from the whole active set (`listValidators()`). Before every
delegation the module reads the validator live and refuses it when it does not exist, is not in the
consensus set in good standing, or charges more than `maxCommission` (10 % unless you set it; many
validators charge 10–15 %). `enrich` can attach an explorer's APR or a logo.

### Stake and position

<Snippet file="earn/src/native-monad.ts" region="monad-stake" />

A stake becomes active at the next epoch, or the one after when it is sent after the epoch's
boundary block (`getEpoch().activatesAtEpoch`; epochs are about 4 hours). Monad keeps a 10 MON
reserve on every account: a stake that would leave less is refused (`getMaxStakeable()`). Rewards
accrue separately in `unclaimedRewards`; claim them or compound them into the stake.

### Unstake and claim

<Snippet file="earn/src/native-monad.ts" region="monad-unstake" />

Only active stake can be undelegated. Each unstake takes a withdrawal slot (0–255 per validator)
and can be withdrawn one epoch after the stake deactivates. The precompile withdraws one request
per transaction, so `claimWithdrawals` may send several. After a full exit the precompile no longer
lists the validator among the wallet's delegations: keep the `id` that `requestWithdrawal` returns,
or pass the validator in `validators`, so the withdrawal is found again.

:::note[Policies]
Staking writes go to the precompile `0x0000000000000000000000000000000000001000`; a Monad
`allowlist` must include it.
:::

## Native NEAR staking

`@anywalletkit/protocol-staking-native-near` stakes NEAR into NEAR's staking pools with
`deposit_and_stake`: no extra contract, no token, the position is the account's balance in each
pool. Your app decides which pools it offers; the module has no default list and refuses to start
without one.

```sh
npm install @anywalletkit/protocol-staking-native-near @anywalletkit/wallet-near
```

### Choose the pools

<Snippet file="earn/src/native-near.ts" region="near-setup" />

`pools: 'any'` lets users pick from the validator set (`listPools()`). Either way a pool must be a
factory pool (`*.poolv1.near` or `*.pool.near`). That check is local, so no RPC answer can pass a
foreign contract off as a pool, and other ids get no RPC call at all. Before every stake the module
reads the pool live and refuses it unless it runs one of the pinned staking-pool builds
(`KNOWN_POOL_CODE_HASHES`, plus your `codeHashes`), answers `is_staking_paused` with `false`,
charges at most `maxFee` (10 % unless you set it; for a `*.pool.near` pool, also the fee it already
scheduled for the next epoch) and sits in the current and next validator sets. `enrich` can attach
an explorer's APR, a name or a logo; the checks do not depend on it.

### Stake

<Snippet file="earn/src/native-near.ts" region="near-stake" />

Show the quote's transactions and fee, then pass the transactions the user confirmed as
`expected`: the write plans again with fresh reads and refuses with `quote-changed` (the new plan
in `details.transactions`) when anything differs. NEAR buys a transaction's whole prepaid gas when
it accepts it, at `min_gas_purchase_price` (ten times the gas price on mainnet), and refunds the
unburnt part a few blocks later. So `upfront` is what the account must hold besides the deposit,
and `fee` is the most it finally pays. A stake leaves `reserve` on the account (0.02 NEAR, never
less than the upfront gas of the largest exit, an unstake that withdraws an unlocked balance first:
about 0.11 NEAR today), so the stake can always be left; `getMaxStakeable()` is the most a stake can
send, and the minimum is 0.001 NEAR. The spendable balance is the account's liquid balance minus
the storage cost its locked balance does not cover.

### Position

<Snippet file="earn/src/native-near.ts" region="near-position" />

Stake in pools outside your list (made earlier, or from another app) is found through fastnear's
indexer (`discover`). When that lookup fails, `listPositions` throws rather than report "no stake",
while balances and requests carry on with the known pools and say `partial: true`. The APR comes
from the protocol's own data: the pool's reward for the last epoch ÷ its stake, annualized by the
measured epoch length, after the pool's fee.

### Unstake and claim

<Snippet file="earn/src/native-near.ts" region="near-unstake" />

Unstaked NEAR can be withdrawn 4 epochs later (an epoch is about 6.9 hours, so about 21–28 hours).
A pool keeps one unstaked balance per account with one unlock time: a new unstake restarts the wait
for everything still unbonding there, so the module refuses it (`timer-reset-refused`) unless you
pass `allowTimerReset: true`. When that balance has already unlocked, the unstake withdraws it
first in the same transaction (`[withdraw_all, unstake]`); if the account can no longer pay both
calls at once, the unstake is refused with `claim-first`: claim, then unstake. A partial unstake that
would leave less than 0.001 NEAR staked, or less than that unstaked (a balance never offered as a
claim), is refused with `below-minimum`: unstake `'all'` instead. The whole of a stake below 0.001 NEAR
can always be unstaked (warning `leaves-dust`). The pool only reports `can_withdraw`:
pass `history` (wallet-near's `createNearHistory`) to date the unlock from the account's last
unstake instead of estimating a range. Exits need only the factory suffix and a known code hash, so
users can always leave a pool that was paused, raised its fee or left the validator set. They do not
depend on the validator set or the epoch either: when those reads fail, unstakes and claims still go
out, with `unlock: null` and positions without `poolInfo`.

:::note[External signers and policies]
The module reads through its RPC (`provider`) and signs only through `account.sendTransaction(tx)`,
with a `NearTransaction` of function calls (`{ receiverId, actions }`, no signer, nonce or block
hash), and through `account.sendTransactions(txs)` when the account has it (one approval for a
claim from several pools). An adapter over a browser wallet (wallet-selector and the like) is
small: pass `provider`, since such an account has no RPC of its own. A watch-only account (`chain`
and `getAddress()`) is enough for every read. The transactions go to the pool account: a NEAR
`allowlist` must include each pool you list.
:::

## Liquid NEAR staking (LiNEAR, rNEAR)

`@anywalletkit/protocol-staking-liquid-near` stakes through the LiNEAR contract family: **LiNEAR**
(`linear-protocol.near`, testnet `linear-protocol.testnet`) and **Rhea rNEAR** (`lst.rhealab.near`,
mainnet only). The account receives a token (LINEAR or rNEAR, 24 decimals) whose price in NEAR grows
with the staking rewards.

```sh
npm install @anywalletkit/protocol-staking-liquid-near @anywalletkit/wallet-near
```

### Set up

<Snippet file="earn/src/liquid-near.ts" region="liquid-setup" />

Each contract is pinned by account id and code hash. Every write reads the contract fresh and
refuses it when its live code hash is not pinned (`unknown-contract-code`: an upgrade needs a new
pin, from a new package version or your own `{ contract, symbol, codeHashes }`, which keeps the
preset's storage behaviour for `linear-protocol.near` or `lst.rhealab.near` unless you pass
`firstStakePaysStorage`) or when it is
paused (`contract-paused`; a missing or failing `is_paused` counts as paused). Both checks apply to
exits too: a paused contract rejects every call anyway. rNEAR can also pause a single feature
(deposits, staking, unstaking or withdrawals) while `is_paused` stays false: `getPoolInfo().pausedFeatures`
lists them, a write whose calls need one is refused with `contract-paused`, and while withdrawals are
paused a request is not `claimable` (`paused: true`). `getPoolInfo()` also shows the price, the
totals, the live code hash with `codeHashKnown`, the liquidity and the protocol fee.

### Stake

<Snippet file="earn/src/liquid-near.ts" region="liquid-stake" />

A stake is one `deposit_and_stake` of exactly the amount; it registers the account in the contract
itself, so there is no `storage_deposit`. LiNEAR stakes the whole amount. rNEAR keeps 0.00125 NEAR
of an unregistered account's first stake for that registration: the quote shows it as `storageFee`
with the warning `pays-storage`, `shares` are for the rest, and a first rNEAR stake below
0.00225 NEAR is refused with `below-minimum`: at or below the fee the contract would fail it, and
above it the module keeps its 0.001 NEAR minimum for the part actually staked. The module only ever builds `deposit_and_stake`,
`unstake`, `unstake_all` and `withdraw_all` to the pinned contract, never `ft_transfer_call` (these
contracts have no `ft_on_transfer`: tokens sent that way are lost). `expected`, `upfront`, `fee` and
`reserve` work as in native staking.

### Position

<Snippet file="earn/src/liquid-near.ts" region="liquid-position" />

`balance` is the token, `total` its NEAR value at the current price. The APR is the price's growth
over `aprWindowEpochs` (24 epochs, about 7 days), read from an archival RPC (`archivalProvider`);
pass `apr` to show your own figure instead.

### Unstake and claim

<Snippet file="earn/src/liquid-near.ts" region="liquid-unstake" />

`requestWithdrawal` takes token units, as the staking interface defines it, and sends their NEAR
value (`unstake_all` for the whole balance). The wait is 4 epochs or more: the contract may add
epochs for large amounts or after its epoch settlement, so a quote knows only the earliest epoch
(`unlock.latestEpoch` is `null`): show `unlock.earliestAt`. The contract's exact epoch
(`getWithdrawalRequests()` or `getAccountDetails().unlockEpoch`) can be read once the unstake is
final. Reads use final blocks, a couple of blocks behind the send's answer, so a read right after
the send still shows the previous unlock epoch (0 on a first unstake): read again until it is at
least `unlock.earliestEpoch`. As in a pool, a new unstake restarts the wait of a balance still
unbonding (`timer-reset-refused` unless `allowTimerReset`), and an unlocked balance is withdrawn
first in the same transaction. A claim also needs the contract to hold the NEAR, which its operator
brings back from the validators each epoch. Until then the request is `awaitingLiquidity` and a claim refuses
with `awaiting-liquidity`: show it as "waiting for the protocol's payout". An unstake that would lock
such an unlocked, still unpaid balance again is refused (`relock-refused`) unless `allowRelock`.

:::note[External signers and policies]
External signers work as with native staking: pass `provider`. The transactions go to the contract
(`linear-protocol.near` or `lst.rhealab.near`); a NEAR `allowlist` must include it.
:::

## Savings crvUSD (scrvUSD)

`@anywalletkit/protocol-lending-curve-evm` deposits crvUSD into Savings crvUSD (scrvUSD) on Ethereum,
an unmodified Yearn V3 vault that holds its crvUSD idle and earns a share of crvUSD borrowing fees.

```sh
npm install @anywalletkit/protocol-lending-curve-evm @anywalletkit/wallet-evm
```

```ts
import { ScrvUsdProtocolEvm } from '@anywalletkit/protocol-lending-curve-evm'

const scrvusd = new ScrvUsdProtocolEvm(ethereumAccount)
await scrvusd.quoteSupply({ amount }); await scrvusd.supply({ amount })   // crvUSD in, scrvUSD shares out
const { source, apy } = await scrvusd.getApyDetails()                      // 'chain' | 'api' | 'api-clamped'
await scrvusd.getPosition(); await scrvusd.withdraw({ amount: 'max' })
```

Before anything moves, the module checks the vault on chain: the chain is Ethereum, the vault is an
EIP-1167 clone of the pinned VaultV3 3.0.4 implementation (code hash), `apiVersion` is 3.0.4 and the
asset is crvUSD. It refuses deposits into a shut-down vault or one that has started lending to
strategies (`allowStrategies` opts in); withdrawals stay open and always pass `max_loss = 0`. An
amount above what the vault can pay now is refused with the available amount, while `'max'` redeems
what it can and says whether that was everything (`complete`). Profit from each weekly report
unlocks linearly over 7 days, so the APY is a variable projection: the Curve API's figure is shown
only when it lies within max(0.5 points, 10 %) of the on-chain one, and is clamped to that band
otherwise. Between the full unlock and the next report the on-chain figure is 0, so the API figure
then shows as at most 0.5 %.

:::note[Policies]
An Ethereum `allowlist` must include the vault `0x0655977FEb2f289A4aB78af67BAB0d17aAb84367` and
crvUSD `0xf939E0A03FB07F59A73314E73794Be0E57ac1b4E` (the approval).
:::

## Module-specific extras

The shared interfaces cover what every module can do. Modules add their own methods on
top: Lido wraps stETH into wstETH, Aave toggles collateral and lists reserves with their
rates and caps, Morpho lists vaults, SSV reports APR history. They are listed in each
package's API reference.
